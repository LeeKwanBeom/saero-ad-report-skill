`interaction: {mode:'index', intersect:false}` 가 PC 세로 콤보 그대로였다 — Chart.js 4 의 index 모드는 `axis` 를 안 주면 **가로(x) 거리**로 가장 가까운 막대 끝·비용 점을 고르므로
누른 줄과 무관하게 가로 위치가 비슷한 날짜의 팝업이 떴다(배포본 04abd00 재현: 10/7 줄 왼쪽 → 9/25 · 가운데 → 9/24 — 14줄 어디를 눌러도 9/24·9/25·9/30 셋 중 하나).
위 판 D 규칙에 다음 한 가지만 더해졌다:

- 01 모바일 모양의 interaction 에 `axis:'y'` — `interaction: {mode:'index', intersect:false, axis:'y'}`. 줄(날짜) 안 어디를 눌러도 그 날짜의 총비용·노출수 팝업(접힘·펼침 같음).
  PC 01(세로 콤보 — x 가 맞음)·09 hourlyChart·06(기본 nearest·intersect — 점을 눌러야 뜸)·02·05·10 가로 막대(막대를 눌러야 뜸)는 그대로.
- 표지·기계 자리: 판 D 그대로(새 기계 자리 0) + validate "레이아웃 판" 이 `axis:'y'` interaction 정확히 1건을 본다(PASS 끝 `· 01 터치 y`).
- 바꾸는 코드: `scripts/apply.py --layout` — meta r2026-10-D 판 → `convert_d_to_e`(meta · 01 mobile() 의 interaction 줄 + 바로 다음 `layout: { padding: {right: 64} },` 줄을 앵커로
  그 한 줄 — 앵커가 없거나 둘이면 변환하지 않고 FAIL), 옛 판·판 B·C 는 사슬로 D 를 거쳐 E. `--layout` 없이 판 D 면
  `[FAIL] apply: ApplyError: 레이아웃 판 meta r2026-10-D ≠ config r2026-10-E — --layout 을 붙여 r2026-10-D → r2026-10-E`. 판 C·D 템플릿(사슬 중간 단계)은 그대로 둔다.
  라이브 확인은 `tests/chart_check.py` 의 "01 모바일 터치 팝업(처음·펼침)" — 줄마다 왼쪽·가운데·오른쪽을 진짜로 눌러 팝업 제목 = 그 줄 날짜(판 D 배포본은 3/42 · 3/129 로 FAIL).
- 이 판도 설계 회차·사용자 결정 없이 바꾸지 않는다.

**판 F(r2026-10-F) — 광고비 잔액 카드**(사용자 결정 2026-10-09 — 기능 추가). 사용자 원문: "현재 보고서 사이트에 스킬을 돌릴당시의 광고비 잔액을 상단 4개의 카드섹션영역에 추가할수 있을까?"
사용자 결정: ① 배치 = KPI 카드 넷 **아래 긴 카드 한 장**(데스크톱·모바일 같은 모양 — 모바일은 위 넷이 2·2, 잔액 카드는 한 줄 전체) ② 보조 줄 = 기준 시각 + 며칠분
(예 `10/9(금) 14:34 기준 · 약 24일분` — 며칠분 = 잔액 ÷ 최근 7일 평균 총비용, 버림 · 7일 이하 빨강 경고 없음) ③ 잔액은 원 단위 버림 · 조회 실패해도 배포는 멈추지 않고
카드에 "확인 못 함"(옛 값을 새 시각으로 보이지 않는다) · 공개 사이트에 잔액이 보이는 것(총 광고비는 이미 공개). 위 판 E 규칙에 다음이 더해졌다:

- 카드: `.kpi-row` 다섯째 자식(넷째 카드 "총 광고비" 바로 뒤) `<div class="kpi kpi-wide" style="--accent:#1c2b2a;">` — 아이콘(지갑 라인 SVG)·`.label` "광고비 잔액"·
  `<div class="value" data-balance="value">`·`<div class="sub" data-balance="sub">`. 모양·글꼴·색은 `.kpi` 그대로(accent 는 넷째 카드 값 — 새 색 0), 한 줄 전체는 CSS 한 줄
  `.kpi-wide{grid-column:1 / -1;}`(데스크톱 4칸·모바일 2칸 모두). 카드 넷 마크업·섹션·서술 표지는 그대로.
- 값(apply 기계 자리 — 매 회차 둘 다 다시 쓴다): 성공 `217,817<span class="unit">원</span>` · `10/9(금) 14:34 기준 · 약 24일분`(평균 0 이면 ` · 약 …` 없음) /
  실패 `확인 못 함`(단위 없음) · `10/9(금) 14:34 조회 실패`(시도 시각). 정의는 아래 "KPI 요약" 의 "광고비 잔액 카드" 줄.
- `data-balance` 속성 덕분에 기존 KPI 앵커(validate `parse_kpi_tiles` · apply 총 광고비 once · compare `_kpi` 의 sub 순번)에 새 카드가 잡히지 않는다 — 카드에 `data-balance` 없는
  `<div class="value">`·`<div class="sub">` 를 쓰지 않는다. 카드 글에 "클릭당 평균"·"일 평균" 을 쓰지 않는다(넷째·첫째 카드 앵커).
- 표지·검사: validate "레이아웃 판" 이 표지(`data-balance` 값·보조 줄 각 config `markers.balance_card` 1 · `.kpi-row` 안 넷째 카드 뒤 · `.kpi-wide` CSS 1)를 보고(PASS 끝 `· 잔액 카드 1`),
  새 검사 "광고비 잔액 카드 = 잔액 기록(balance.json)·며칠분" 이 값·보조 줄을 잔액 기록·CSV 로 독립 대조한다(validate 25개). 라이브 모양은 `tests/chart_check.py` "상단 잔액 카드 한 줄 전체(판 F)"(390·1280).
- 바꾸는 코드: 5단계 `scripts/balance.py`(GET 1회 → `work/balance.json`) → `scripts/compute.py --balance`("잔액") → `scripts/apply.py --layout` — meta r2026-10-E 판 → `convert_e_to_f`
  (meta · `</style>` 앞 CSS · 넷째 카드 끝 + `.kpi-row` 닫힘 앵커(정확히 하나) 사이에 카드 — 판 E 인데 표지가 이미 있으면 FAIL), 옛 판·B·C·D 는 사슬로 E 를 거쳐 F.
  `--layout` 없이 판 E 면 `[FAIL] apply: ApplyError: 레이아웃 판 meta r2026-10-E ≠ config r2026-10-F — --layout 을 붙여 r2026-10-E → r2026-10-F`. 판 F 인데 compute.json 에
  "잔액" 이 없으면 `[FAIL] apply: … "잔액" 없음`(카드를 옛 값으로 두지 않는다).
- 이 판도 설계 회차·사용자 결정 없이 바꾸지 않는다. 카드 글(라벨·보조 줄 꼴)을 바꾸려면 코드 전에 사용자에게 묻는다.

4개 타일: 총 노출수 / 총 클릭수 / 평균 클릭률 / 총 광고비
각각 sub 문구로 일 평균 또는 클릭당 평균 비용을 표시한다.

광고비=ink. 카드 왼쪽 4px 강조선 + 우상단 라인 아이콘 + 원형 배경 장식.

**광고비 잔액 카드(판 F, 2026-10-09)** — 4개 타일 아래 한 줄 전체 카드 하나(위 "판 F" 문단). 강조색 = ink(광고비와 같은 값), 아이콘 = 지갑 라인.

  기준 = 읽은 시각 KST `M/D(요일) HH:MM`(분 아래 버림) · 창 = 키워드 보고서 `일별` 의 **달력 날짜**로 집계 마지막 날까지 7일(첫날보다 앞은 자른다 · 행 없는 날 = 0원) ·

  읽은 날(KST)이 집계 마지막 날 이하이면 compute `[FAIL]`(지난 회차 기록 — 데이터는 언제나 어제까지). 조회 실패 기록이면 값 없이 `{"상태": "fail", "기준": …}`.

  실시간 차감으로 보임 [추론]). 쿠폰 잔액이 이 값에 드는지·광고시스템 화면 숫자와 끝자리가 같은지는 [미확인] — 첫 적용 회차에 사용자가 화면과 한 번 대조한다.

## 01. 일별 추이

노출수 막대 + 총비용 라인의 콤보 차트(`dailyChart`). 숫자·배열은 하나(아래 두 모양이 같은 data 를 쓴다 — 판 C).

### PC 모양(화면 폭 > config `report_layout.mobile.max_px`)

- 막대(노출수) 라벨은 막대 **하단**, 선(총비용) 라벨은 선 **위쪽** — 겹침 방지
- 범례는 `bottom` 고정. top-right에 두면 마지막 날짜가 최고치일 때 라벨과 겹친다
- 차트 컨테이너: `<div class="scroll-x" style="overflow-x:auto;">` 안에
  `<div style="height:280px; min-width:{max(날짜수×per_day_px, floor_px)}px;">` — 두 값은 config `chart_min_width`
- x축 ticks: `maxRotation:0, autoSkip:false`
- (판 C) 가로 스크롤은 오른쪽 끝(최신 날짜)에서 시작 — 왼쪽 페이드가 이전 날짜를 알린다

### 모바일 모양(판 C — 화면 폭 ≤ max_px)

가로 막대: 날짜 세로축 최신 위(`y.reverse` · `autoSkip:false` — 날짜 tick 전부) · 노출 막대(#cdeee7) 라벨은 막대 시작 쪽(`anchor start · align right`) ·
총비용 점·선(mintDark) 라벨은 점 오른쪽(`anchor center · align right` — 점이 같은 행 노출 라벨 안쪽이면 그 라벨 뒤로 밀어 글자 겹침 0) · 값축 위 x '노출수'·아래 x1 '비용(원)' ·
오른쪽 여백 64px(비용 라벨 자리) · 범례 bottom 그대로 · 컨테이너 높이 = 그리는 날짜 수 × 26 + 90px(config `row_px`·`pad_px`, JS 가 런타임에 — HTML 의 280px·min-width 는 PC 값 그대로).
(판 D) 처음에는 최근 14일만(config `mobile.recent_days` 01 — 42일이면 9/23~10/6 · 454px) + 차트 카드 아래 `이전 N일(M/D~M/D) 펼치기` 버튼(03 summary 글꼴) — 누르면 전 기간·다시 누르면 접힘,
인쇄는 전 기간(위 "판 D" 문단). 날짜 ≤ 14 면 버튼 없이 전부.
(판 E) 터치 팝업은 누른 줄(날짜)의 총비용·노출수 — `interaction: {mode:'index', intersect:false, axis:'y'}`(axis 를 빼면 가로 위치로 날짜를 골라 다른 날짜가 뜬다, 위 "판 E" 문단).

### 인사이트 박스 (차트 카드 바로 아래)

특정 주간 패턴이 관찰될 때만 유지한다. 패턴이 사라지면 박스 자체를 빼는 것도 고려.

구성:
1. **① 일별 지표 통합표** — 날짜 / 노출 / 검색 / 콘텐츠 / 클릭 / CTR / CPC (최근 5일)
2. **② 플레이스 광고 평균노출순위** — 5칸 숫자 그리드.
   정의(compute.py `01.플레이스순위5`·`순위민트`): 날마다 플레이스 그룹 행의 노출 가중순위(순위 0 행 제외, 소수 2자리),
   닷새 중 **가장 작은 값 한 칸**에 민트 강조. 누적값은 `플레이스누적가중순위`.
   소제목에 `(06번의 파워링크 키워드 순위와는 다른 지표)` 반드시 병기.
   01번은 플레이스 광고 순위, 06번은 파워링크 키워드 순위로 대상이 다른데
   이름이 같아 혼동된 이력이 있다
3. **③ 해석 문장** — 구분선(`border-top`) 두고 `.note-mint`로

해석 문장은 매주 다시 쓴다. 표만 갱신하고 문장을 두면 사실과 어긋난다.
톤은 단정 대신 "가장 유력하게 보이는 해석" 수준으로 낮춘다.

**길이(2026-10-06 — 글 줄이기, "서술 공통 규칙")**: 박스는 ①·②·③ 셋뿐 — 박스 머리의 하루 요약 두 줄(옛 "M/D(요일) 노출 …"·
"9/6부터 M/D까지 N일 …")과 ① 표 아래 하루 분해 각주(플레이스/파워링크 노출·CTR·CPC 섞임 설명)는 **두지 않는다**(하루 요약은 section-desc 한 줄이
그 자리 — 머리글이 10/6 회차에 안 바뀐 채 배포된 자리). ② 아래 각주 = 닷새 순위 나열 + `누적 가중평균은 A → B위` + "~어려워 보임" 한 문장.
③ = 결론 한 줄(콘텐츠 지면 없는 날 N일 · 누적 CTR) + compare 가 읽는 세 문장(`검색 지면만 계산하면 <b>N%</b>(노출 N·클릭 N)` ·
`하루 평균은 N원·클릭 N건·CPC N원으로, 상향 전 9/1~9/16(하루 평균 N원·N건·CPC N원)` · `콘텐츠 노출 N회`) + 상태 한 줄(상향 유지 결론 그대로 — 재상정 조건 미달).
결정 날짜("2026.09.xx 사장님 확인"·"회차 완료 건")는 쓰지 않는다(checklist [의도된 동작] 10 이 정본).

표 2개를 따로 두지 말고 컬럼으로 합칠 것 — 원래 ①CTR·CPC표 + ②지면별표 두 개였는데
모바일에서 01번만 3~4화면을 차지해 통합했다. 앞으로도 길어지면 표를 늘리기보다
컬럼으로 합치는 쪽을 우선한다.

## 04. 캠페인 상세 지표

컬럼 9개 고정:
`광고 유형 / 광고그룹(키워드) / 노출수 / 클릭수 / 클릭률 / 총비용 / 평균CPC / 예산 비중 / 평균순위`

- **예산 비중**은 매주 `각 광고 총비용 ÷ 전체 광고비`로 재계산. 합이 100%인지 검산.
  정의(compute.py `04.rows[].비중`): **최대잔여법** — 소수 1자리로 잘라 남는 0.1을 소수부가 큰 순으로 배분해 합을 100.0으로
  맞춘다. 단순 반올림과 다를 수 있다(09-24 3.955→3.9, 09-25 92.545→92.6). 02번 section-desc 비중도 같은 값.
  행 순서: 플레이스 1행 뒤 파워링크 그룹을 총비용 내림차순, 평균순위는 소수 2자리
- 신규 키워드 행에는 `(8/31 신규)` 같은 표기를 민트색 작은 글씨로 병기
- 평균순위는 파워링크에만 적용. 플레이스는 `—`
- CPC 값에 `.ctr-high`(민트 강조)를 **쓰지 말 것** — 07번에서 같은 색이
  "클릭률 기준(config `ctr_high_threshold`) 이상"을 뜻하므로 같은 색이 다른 의미로 쓰이면 혼동된다

표 아래에 CPC 해석 문구를 `.note-mint` + `.note` 2단으로 둔다(2026-10-06 길이: note-mint = "M/D까지 CPC A원 vs B원 — 격차 A → B배 · 예산의 N%가
플레이스(지난 회차 N%)" 한 문장, note = 성격 차이 한 문장 + 파워링크 마지막 날 한 문장(`비중은 A → B%`) + "예산은 현행 유지(사용자 결정)").
플레이스 CPC와 파워링크 CPC를 대비시키되, **단정적으로 "파워링크로 옮겨라"라고
쓰지 말 것**. 두 광고의 성격 차이(플레이스=매장명·지도 검색이라 방문 의도가 더
뚜렷할 수 있음 / 파워링크=저렴하지만 클릭 절대량이 적음)를 같이 서술해 균형을 잡는다.

각주: 평균순위가 파워링크 전용 지표라는 점 + 제외 그룹이 OFF 상태여서 뺐다는 점
(그 그룹에 키워드 10개가 등록돼 있다는 사실 포함).

**새 지표를 추가할 때**: 표/카드를 새로 만들기 전에 이 표에 컬럼 하나를 추가하면
되는지 먼저 확인한다. 새 표를 만들면 같은 숫자를 두 곳에서 매주 갱신해야 하고
불일치가 생긴다. 실제로 중복 표를 만들었다가 되돌린 사례가 2건 있다.

## 06. 파워링크 키워드 노출순위 추이

라인 차트(`rankChart`) + 키워드 매칭 방식 비교표.
(판 C) 모바일(≤ config `report_layout.mobile.max_px`)은 가로·최신 위·순위 라벨 41개 — 날짜 세로축 최신 위 · 순위축 위 reverse·min 1(1 이 오른쪽) · 점 오른쪽 순위 라벨
(`toFixed(2)` — compute 2자리 값 그대로, 모바일에만) · 컨테이너 높이 = 날짜 수 × 22 + 70px. 정의·전 기간 배열 그대로(화면만), 제목 문구 '… 일별 평균순위 · 낮을수록 상단' 그대로
(광고 노출 위치 — section-desc 와 짝). PC 는 그대로 + 스크롤 시작 최신 쪽.
(판 D) 모바일 처음에는 최근 14일만(config `mobile.recent_days` 06 · 높이 14 × 22 + 70 = 378px) + 차트 카드 아래 `이전 N일(M/D~M/D) 펼치기` 버튼 — 01 버튼과 따로, 인쇄는 전 기간.

정의(compute.py `06.rankChart`·`노원역순위`): 라인 차트 값 = **노원역필라테스 그룹 전체**(직접 등록 + 자동매칭 `-`)의
날짜별 노출 가중순위, 전 기간. 직접 등록 키워드만이면 배포본과 하나도 안 맞는다(2026-09-26 실측 0/31).
section-desc의 "평균 N위"는 같은 그룹의 누적 가중순위.

비교표는 직접 등록 키워드 vs 네이버 자동매칭(`-`)의 노출/클릭/순위/비용 대비.
정의(compute.py `06.직접`·`자동`): 파워링크 4그룹 합산, 순위는 **소수 1자리**(04번 표는 2자리).
자동매칭이 직접 등록보다 성과가 좋은 경향이 관찰되고 있어 확장검색 활용 검토
근거로 쓰인다.

  독립된 라인 차트로 승격

## 07. 실제 검색어 분석

**데이터 출처 주의**: "검색어 보고서"는 파워링크 전용이 아니라 **플레이스+파워링크를
합친 계정 전체 데이터**다. 섹션 제목에 "— 파워링크"를 붙이지 말 것. 예전에 잘못
붙였다가 2026.09.02에 삭제한 이력이 있다.

레이아웃: 이 섹션 전용 `grid-2-07` 클래스(1.8fr:1fr) 사용. 일반 `grid-2`를 쓰면
좌측 표 컬럼이 찌그러진다. `.grid-2-07 > *{min-width:0;}`도 함께 필요하다.

### 좌측 카드

**(1) 정식 표** — 컬럼 순서 고정:
`검색어 / 매칭 / 노출 / 클릭 / 클릭률 / CPC / 총비용`
(CPC가 총비용보다 앞. "비용"이 아니라 반드시 "총비용"으로 표기)

- 클릭 2건 이상인 검색어만, 클릭수 내림차순, **개수 제한 없이 전부**.
  정의(compute.py `07.정식표`): 검색어 보고서를 **검색어 단위로 합산**(검색 유형이 갈린 행은 노출·클릭·비용을 합친다).
  클릭 동률 → 노출 내림차순. 경쟁사 검색어는 이 표·클릭1건·클릭0 목록에서 빼고 아래 경쟁사표로
- 매칭 컬럼은 뱃지로: 일치=`<span class="tag tag-mint">일치</span>`,
  확장=`<span class="tag tag-ink">확장</span>`.
  "일치(유사검색어)"도 일치 계열이므로 민트 뱃지
- 클릭률 기준(config `ctr_high_threshold`, 현재 4%) 이상인 행만 `<td class="num ctr-high">`. 표 하단에 범례 문구 포함.
  뱃지는 노출이 많은 검색 유형으로, 일치·확장 노출이 **동률이면 직전 뱃지 유지**(compute.py `*동률` 표시)

**(2) 클릭 1건 검색어** — 얇은 구분선 두고 컴팩트 목록.
`검색어(노출수회/총비용)` 형태로 한 줄 텍스트 나열. 경쟁사 브랜드명은 제외.
(레이아웃 판) 머리글이 `<details class="fold">` 의 summary `클릭 1건 검색어 (N개 · 펼치기)`, 목록 div 는 그 안(기본 닫힘 — 맨 위 "레이아웃 판" 표).
정의(compute.py `07.클릭1`): 노출 내림차순, 노출 동률은 직전 순서 유지. **동률 원칙(2026-09-27)**: HTML의 동률 순서는 직전 순서 유지가 정본. compute.py 출력의 동률 순서(클릭1건 2차 키 총비용↓ 등)는 참고이며 compare.py는 집합+정렬 방향만 본다.

**(3) 노출은 있으나 클릭 0건인 검색어** — 또 구분선 두고 컴팩트 목록.

## 10. 검색 지면 vs 콘텐츠 지면

가로 막대 비교. 막대 끝에 실제 숫자 라벨.

A = `검색/콘텐츠 매체 == 검색` 이면서 `매체이름`이 `네이버`로 시작하는 매체 **전부**(통합검색·플레이스·검색탭·광고더보기),

### 작성 기준

11번도 12번과 같이 `validate.py`가 검사하지 않는 구간이다. 아래 기준을 지켜
쓰고, 마지막의 수동 검사로 확인한다. (2026-09-10 신설. 당시 배포본 11번은
15개 항목·항목당 4~6문장이었고, 매주 같은 자리에 같은 문장이 반복되는 상태
항목과 12번에 있어야 할 조치 문장이 섞여 있었다.)

**1) 관찰과 해석을 한 문장 안에서 나눈다.** 항목의 첫 문장은 숫자가 붙은
사실(무엇이 얼마였나)이고, 해석은 그 뒤에 "~로 보임 / ~일 수 있음"으로
따로 쓴다. 숫자 없는 서술("계속 늘고 있음", "여전히 좋음")은 쓰지 않는다.
비교는 반드시 기준값을 병기한다 — 지난주 값, 평균, 또는 개업 이후 누적 중
어느 것과 비교했는지 괄호로.

**2) 직전 회차 11번을 항목별로 판정한다.** 배포본 11번의 모든 항목을
**유지 / 뒤집힘 / 근거 소멸** 중 하나로 판정한다. 뒤집힌 항목은 이번 11번의
**맨 위**에 "지난주 관찰이 뒤집힘 — …"으로 올린다(조용히 고쳐 쓰지 않는다).
근거가 사라져 빼는 항목은 왜 뺐는지 한 줄을 남긴다. 12번 작성 기준 1)·2)와
같은 규칙이다.

**3) 항목 수 상한과 순서.** 최대 **8개** + `(참고)` 최대 2개. 순서는
① 뒤집힌 결론 → ② 이번 주 새로 생긴 변화(움직인 광고비가 큰 순) →
③ 유지 중인 관찰 → ④ `(참고)`. 매주 반복되는 상태 항목(모바일 비중·최고치
날짜·최다 시간대·제외 그룹·지역 비중·자동매칭 우위)은 **값이 의미 있게
움직였을 때만** 독립 항목으로 올린다 — 기준은 비중이면 ±3%p, 순위·시간대면
자리가 바뀌었을 때. 움직이지 않았으면 마지막 항목 하나에 "변화 없음:
모바일 82.7%(지난주 83.5%) · 최다 시간대 15시 2회차 연속 · …"처럼 한 줄로
묶는다.

**4) 12번과 역할을 나눈다. 11번은 "무슨 일이 있었나", 12번은 "그래서 뭘
하나".** 11번에 조치 문장("~정리가 필요해 보임", "~할 시점", "~옮기는 정리")을
쓰지 않는다 — 그 내용은 12번 항목이다. 반대로 **12번에서 완료·철회·보류로
결정된 것을 11번이 "미반영"·"필요"로 서술하면 안 된다.** 이 모순을 막기 위해
**12번을 먼저 확정하고 11번을 맨 마지막에 쓴다**(SKILL.md 5단계의 "순서대로
갱신"에 대한 예외). 사용자가 채팅에서 내린 결정(의도적 보류 등)은 11번에서
그 결정이 난 것으로 서술한다.

**5) 기간 표현은 실제 단위로.** "N주째"는 실제로 N주가 지났을 때만 쓴다.
회차가 며칠 간격으로 돌면 "N회차 연속"이라고 쓴다. 개업 15일차 리포트에
"5주째 유지"가 실린 사례가 있다(2026-09-10 배포본).

**6) 길이.** 항목당 **굵은 결론 1문장 + 근거 괄호**(80자 안팎 — 2026-10-06 글 줄이기, 옛 기준 "3문장 이내"),
첫 문장만 읽어도 결론이 서게 쓴다. 둘째·셋째 문장(하루 분해·지난 회차 서술)은 쓰지 않는다. "변화 없음" 항목은 값 나열만.
같은 숫자를 다른 섹션에서 이미 보여주고 있으면 숫자 대신 "(04번 표 참고)"로 가리킨다.
경쟁사 판정(07번 ①)은 `(참고)` 한 줄로(SKILL.md (1-1) 세 곳 관행 — 각 한 줄). 판정 줄도 한 문장(`지난 회차 11번 N개 항목 판정: 유지 N · 뒤집힘 N · 근거 소멸 N` —
뒤집힌 항목 이름 + 이번 요약 개수).

**수동 검사 (배포 전)** — 아래 6개 중 항목 수·판정 줄·금칙어·12번 모순(잔존 문구)은 2026-09-26부터 `validate.py`가
검사한다(19~21번). 숫자 일치와 사실 여부는 여전히 사람이 본다.
- 모든 숫자가 이번 CSV 재계산값과 일치하는가 (지난주 값을 인용한 경우 직전
  배포본과 일치하는가)
- 직전 배포본 11번의 항목 수 = 유지 + 뒤집힘 + 근거 소멸 개수인가
- 조치 문장 0건인가 — `필요`, `시점`, `할 것`, `검토`로 검색해 확인
- `주째` 0건인가(실제 주 단위가 아니면)
- 12번의 완료·철회·보류 항목과 어긋나는 서술이 0건인가
- 항목 8개 이하, `(참고)` 2개 이하인가

### 작성 기준

이 섹션은 리포트에서 유일하게 스크립트 검산이 없는 구간이다(`validate.py`는
12번의 금칙어·잔존 문구와 2026-10-10 장부·플레이스 행 꼴(아래 6)만 본다 — 무엇을 넣을지는 보지 않는다). 그래서 무엇을 넣을지는 아래 기준을 지켜 판단한다.

**1) 이월 판정 의무화.** 배포본(직전 회차) 12번의 모든 항목을 이번 주 데이터로
**완료 / 진행 / 철회** 중 하나로 판정하고, 판정 근거가 된 숫자를 함께 적는다.
판정 없이 조용히 사라지는 항목이 있으면 안 된다. 지난주 문장을 그대로 두고
숫자만 바꾸는 것도 금지 — 11번과 같은 이유다.

**2) 철회 사유 한 줄.** 근거가 사라져 뺀 항목은 왜 뺐는지 한 줄로 남긴다.
경쟁사 "자연 소멸" 처리와 같은 방식이다. 조용히 빼면 다음 회차에 신규로 다시 올라온다.
자리(2026-10-06) = 표 아래 note 의 `· 이월 판정:` 줄(철회 0 이면 "철회 0").

**길이(2026-10-06 — 글 줄이기)**: 항목 칸 = 상태 태그 + **상태 줄(굵게, 07번 ② 와 같은 값)** + "등록 여부는 스킬이 registry 로 판정" 같은 규칙 한 구 +
`다음 회차 판정:` note 한 줄. 표 아래 note = `· 정렬` · `· 이월 판정`(철회 사유 자리) · `· 신규 없음` · `· 경쟁사는 액션 항목으로 올리지 않음`(07번 ① 한 줄) 각 한 줄.
날짜별 등록 개수 나열("2026.09.20 등록한 17개, …")·판정 되풀이·확장·클릭 0 하루 서술은 쓰지 않는다 — registry·last-audit 대조 목록이 정본.
표 아래 "집계 기준" 다섯 항목도 각 한 문장(회차마다 바뀌는 숫자 없이 — 차이 숫자는 08·09번 각주).

**3) 성공 판정 조건 명시.** 모든 항목에 "다음 회차에 무엇을 보고 성공·실패를
판단할지"를 한 줄로 붙인다. 그래야 다음 주에 1)의 이월 판정이 가능해진다.

**4) 항목 수 상한과 정렬.** 최대 7개. **비용 영향이 큰 순**으로 정렬한다.
완료(`✓`) 항목은 이 7개 상한에 포함하지 않는다.

**5) N주 연속 미반영은 리포트가 아니라 채팅으로.** 같은 항목이 3주 이상 반영되지
않고 반복되면, 리포트에 또 적기 전에 **왜 진행이 안 되고 있는지 사용자에게 먼저
묻는다.** 실행이 막힌 이유(권한·시간·의사결정 보류)를 모르는 채 같은 문장을
반복하면 표가 길어지기만 하고 아무것도 안 바뀐다.

**6) 매출 작업 행(2026-10-10 — 설계안 A 주간 성과 장부 + C 플레이스 화면 손보기, 사용자 결정 "추천대로 하자").** 첫 적용부터 매 회차:
- **장부 행 1개** — 안쪽 HTML 은 `scripts/leads.py` `row_html(R)`(R = 그 회차 compute.json) 그대로: `매주` 태그 + **`<M/D>까지 장부 기준 판정 = <낱말>`**(굵게) + 비교 규칙 한 구 +
  `다음 회차 판정:` note. 낱말 = compute `성과장부.판정`(config `leads.verdict_words` — '판정 전' 은 `(N/<min_weeks>주)` 를 붙인 꼴). 장부 행은 매 회차 같은 자리에 있는 것이
  정상이라 **5)의 3주 미반영 규칙 밖**(판정 낱말만 바뀐다 — 채팅 질문 대상 아님).
  **장부 숫자(문의·체험·등록·매출·스마트플레이스 통계)는 01·11·12 어디에도 쓰지 않는다**(config `leads.publish` = verdict — compute 성과장부에 건수가 없고, validate

- **플레이스 행** — `scripts/place.py` `rows_html(R)` 의 순서 그대로: 바꾼 항목(✓ 태그 · `<P 번호> <문구> — <바꾼 날> 바꿈 · <M/D>까지 판정 = <낱말>` — 낱말 = config
  `place_checklist.verdict_words`, 측정 중은 `(n/<window_days>일)` 를 붙인 꼴 · 판정이 난 뒤 config `final_show_days` 일까지 · 장부 판정 낱말만 인용) + ✗ 항목(`화면 손보기` 태그 ·
  `<P 번호> <문구> — <M/D>까지 상태 = ✗` — config 순서 위 `items_in_12` 개, 성공 판정 조건 = 바꾼 날 다음 날부터 `window_days` 일 플레이스 **검색 지면** 하루 클릭·CTR 이
  바꾸기 전 같은 일수 대비 **둘 다** `band_pct` 띠 위면 좋아짐). ✗ 행은 4)의 상한(config `place_checklist.max_open_rows_12`)에 들고, ✓ 행은 들지 않는다.

  이름 블록과 **바이트가 같으면 `[FAIL] 서술 미교체 <자리>`**(도장 없음). 같은 기간(2-1 같음 경로·첫 적용 경로 C)·직전 배포본에 표지 없음(첫 적용)이면 `[주의]`로 생략, 작업본 표지 0 은 FAIL.
- **고정** = 표 설명·규칙 + compare 가 숫자를 대조하는 한 줄(문구가 같아도 되는 자리) — narrative 대조 안 함. 그래도 교체 대상(`rep`)으로 표지를 둔다.
  compare 가 읽지 않는 **지난 회차 값·방향어**("A → B", 그대로/줄어듦)를 쓰는 한 줄은 고정이 아니라 **매회차**로 두고 `M/D까지`를 넣는다(04-desc — 고정이면 지난 회차 문장이 그대로 남아도 모든 검사를 통과한다, 2026-10-06 자기 검토 막음).
- 5단계 서술 교체 = 그 회차 n<날짜>.py(저장소 밖 스크래치)가 `rep('<자리>', 새 문장)` — 이 표가 자리 이름의 정본(SKILL.md 5단계·code-tab.md 3절 5행이 여기를 가리킴).
  **첫 적용**(직전 배포본에 표지 없음)만 옛 글 시작 문구(숫자 없는 리터럴)로 블록을 찾아 표지를 넣고, 01 머리글 두 줄·01 ① 표 아래 하루 분해 각주·07 ✓ 줄·07 ⚠️ 줄을 지운다
  (본보기 위치는 last-audit "기능 추가 구현 기준선(리포트 읽기 쉽게 — 회차 1 글)" 절).
